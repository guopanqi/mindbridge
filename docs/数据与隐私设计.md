# MindBridge AI · 数据与隐私设计

> 本文说明 MindBridge 如何接入企业办公软件中的员工数据、如何处理其中的敏感内容、以及在每一个环节上系统主动放弃了哪些能力。
>
> 用途：① 复赛方案书「风险分析」章节的素材；② Demo 实现的规格说明。

---

## 0. 一句话原则

> **系统不读员工的聊天。是员工把那一句话，自己递过来的。**

整套数据设计都从这句话倒推。任何需要企业开通全量会话读取的方案一律排除——那是监控，不是关怀。一个员工只要怀疑自己被监听，这个产品对他就已经失效了，后面再好的疗愈资源都送不进去。

---

## 1. 数据接入的四档权限

我们把办公软件里可能拿到的数据，按**谁来授权、门槛多高**分成四档。这个分法比按"数据类型"分更有意义，因为决定一个方案能不能落地的，从来不是技术，是授权。

| 档 | 名称 | 谁授权 | 拿到什么 | 我们的态度 |
|:---|:---|:---|:---|:---|
| **L0** | 员工主动转发 | **员工本人，每次单独同意** | 员工这一次递过来的 1–5 条消息 | ✅ **主用** |
| **L1** | 标准 API 元数据 | 企业安装应用时的常规授权 | 考勤、审批、日程、待办等行为数据，**不含任何消息内容** | ✅ **主用** |
| **L2** | 指定群消息读取 | 企业管理员 + 群内成员知情 | 机器人所在群的消息 | ⚠️ **可选，逐群判定** |
| **L3** | 会话内容存档 | 企业级合规开通 | 全量消息内容与完整时间戳 | ❌ **不申请** |

L0 的位置值得强调：**它需要的企业授权是零**——比读一条考勤记录还低。它不在权限阶梯上，因为它根本不向企业要权限，只向员工本人要，而且一次只要一次。

## 2. 三平台能力对比

| 能力 | 企业微信 | 钉钉 | 飞书 |
|:---|:---|:---|:---|
| **L0 转发给应用/机器人** | ✅ 自建应用会话 | ✅ 内部机器人 | ✅ 机器人 |
| 卡片交互（做确认屏） | 弱，需跳 H5 | 强 | 最强，卡片内可完成 |
| **L1 考勤打卡** | ✅ | ✅✅ 最强 | ✅ |
| **L1 审批（加班/请假/调休）** | ✅ | ✅✅ | ✅ |
| **L1 日程密度** | ✅ | ✅ | ✅✅ 含忙闲状态 |
| **L1 待办积压** | ⚠️ 弱 | ✅ | ✅✅ |
| **L1 个人消息条数** | ❌ | ❌ | ⚠️ 管理后台数据报表或可（待核实） |
| **L1 @次数 / 夜间消息占比** | ❌ | ❌ | ❌ |
| **L2 读取指定群消息** | ❌ 无对等能力 | ❌ 无对等能力 | ✅ 限机器人所在群，单聊读不到 |
| **L3 会话存档** | ✅ 需开通 | ⚠️ 需专项申请 | ⚠️ 需专项申请 |

**关键结论**：`@次数`、`夜间消息占比` 这类"看起来很有说服力"的指标，三家在标准 API 下都拿不到——它们只存在于 L3。而 L3 我们不用。

### 行业与平台的对应

| 行业 | 主流平台 | 理由 |
|:---|:---|:---|
| 教育（中小学） | **钉钉** | 家校群、班级圈、家校本是钉钉主场，公立校渗透率高；考勤对教师尤其准（早读到晚自习） |
| 互联网 / IT | 飞书 | 卡片交互强，OKR 数据可作压力信号 |
| 金融 / 制造 / 医护 / 国企 | 企业微信 | 合规审计与私有化部署要求 |

> Demo 统一采用钉钉演示，以降低理解成本。三平台能力差异不影响方案成立——L0 与 L1 三家都支持。

## 3. 我们停在 L0 + L1

这不是保守，是因为**那三个拿不到的指标，我们其实不需要**。

以教师场景为例：

| 想要但拿不到（属 L3） | 能拿到且更有说服力（属 L1） |
|:---|:---|
| 家长群夜间消息 412 条 | 在校时长中位数 **11.2 小时**（早读 7:10 → 晚自习 18:20） |
| @我 37 次 | 连堂课时 **22 节/周**，超基准 30% |
| 22 点后消息占比 61% | 加班调休审批 **14 次**，其中 **9 次落在周末** |

右侧全部来自考勤与审批的标准接口，**一个字的聊天内容都没有碰**，而对教师的说服力更强——它说的是这个人的一天有多长，不是他的手指有多忙。

于是分工清晰：

> **忙碌程度靠 L1 的量，情绪刺痛点靠 L0 的质。中间两档可以完全跳过。**

这让方案书能写下一句很硬的话：

> **MindBridge 不申请任何一家办公软件的会话读取权限。**

## 4. 匿名化机制

### 4.1 入口即抛弃

员工从任何入口进入系统，真实身份在**入口处**就被单向哈希，此后系统内不存在任何可还原的身份信息。

```
钉钉机器人收到消息 → userid ┐
                            ├→ HMAC-SHA256(userid + salt) → 4A6B
网页应用授权登录   → userid ┘

salt 由独立第三方托管，企业不可获取
```

- **单向**：从 `4A6B` 反推不出 `userid`
- **盐不在企业手上**：企业即使拿到全部数据库，也无法重建对应关系
- **两个入口天然同一身份**：同一个盐、同一个算法，机器人会话和网页应用自动落到同一个匿名 ID，不需要额外做账号打通

### 4.2 呈现给人的是化名，不是编号

系统内标识为 `4A6B`，呈现给员工与疗愈师时显示为「小溪-4A6B」。纯编号会让人觉得自己是个案例，化名让人觉得自己是个人。

## 5. L0 · 主动转发与脱敏

### 5.1 方向必须是反的

不是「在 MindBridge 里浏览我的聊天」，而是「在聊天里选 MindBridge」：

```
员工在群里被某句话刺到
  → 长按那条消息 → 转发 → 选「MindBridge」
  → 消息进入机器人会话
```

这不只是交互偏好，是**权限模型的硬约束**：三家平台都不允许第三方应用读取用户的会话列表。「在应用里浏览我的群聊」这个界面，技术上根本做不出来。

而这个方向反转，恰好就是整套设计的伦理内核：

> **我们不去读员工的聊天——是员工把那句话递给我们。**

### 5.2 粒度

| 规则 | 值 | 理由 |
|:---|:---|:---|
| 默认 | **1 条** | "最刺痛我的那一句"信息密度最高 |
| 上限 | **5 条** | 有时需还原冲突：对方说什么 → 我怎么回 → 对方又说什么 |
| 整群导入 | **禁止** | 噪音大、第三方隐私面无限扩大，且技术上本就做不到 |

### 5.3 脱敏当场可见

转发进来后，系统立即展示脱敏前后对照，让员工**看见脱敏确实发生了**，而不是听我们承诺：

```
原文                            我收到的
李梓涵妈妈：老师你怎么教的…  →  家长A：老师你怎么教的…
三年级2班家长群(48)          →  某家长群
138****2917                  →  已移除

✓ 已抹除 2 个姓名 · 1 个群名 · 1 个手机号
```

脱敏对象：**人名、群名/组织名、手机号、工号、身份证号、住址、金额**。

### 5.4 三种去向，员工自己选

| 选项 | 行为 |
|:---|:---|
| **只让 AI 看这一次**（默认） | AI 回复完成后**立即清空引用正文**，仅保留"来自某家长群 · 1 条"这行元信息 |
| 存进我的情绪线索 | 保留在本人可见的时间线中，随时可删 |
| 撤回，不用了 | 立即删除，不参与任何分析 |

「用完即焚」由代码兑现，不是口头承诺——卡片上会显示"内容已按你的选择销毁"。

### 5.5 脱敏保护的是谁

需要诚实说明：那条消息本来就躺在钉钉里，转发并不增加平台的知情。**脱敏保护的不是传输过程，而是此后的一切**——MindBridge 的数据库、疗愈师看到的内容、任何导出的报表里，都不会出现家长的真实姓名。

## 6. 引用内容如何参与分析

这是技术上最容易出错的地方。**如果把家长的话直接丢进情绪分析，会把家长的攻击性算成员工的情绪**，读数就错了。

因此分两条通道：

| 输入 | 作用 | 明确不做 |
|:---|:---|:---|
| **员工自己说的话** | 产出情绪标签与预警等级 | — |
| **转发进来的引用** | ① 场景识别　② 强度加权 | **不产出情绪标签** |

场景识别对应到行业疗愈方案：

| 场景 | 触发词 | 对应疗愈路径 |
|:---|:---|:---|
| 家校沟通 | 家长、成绩、作业、家长会、投诉 | ABC 情绪理论工作坊 |
| 客户冲突 | 客户、退款、差评、工单 | 心流插花 / 正念+芳香 |
| 上下级 | 领导、汇报、批评、复盘、背锅 | 非暴力沟通 / 跨团队疗愈小组 |
| 同事协作 | 对接、推诿、甩锅、配合 | 跨团队疗愈小组 |

### 只转发不说话

真实场景中，人经常是扔过来一段、一个字不打。此时系统**不做判定，先提问**：

> 「你把这段转过来，是它哪一句让你最不舒服？」

这既是伦理选择（不替人下结论），也是技术必需（不从第三方的话里推断员工的情绪）。它是「AI 只读数、不诊断」这条原则第一次在交互上被真正兑现。

## 7. L1 · 元数据的边界与呈现

### 7.1 用什么，不用什么

| ✅ 采集（标准接口） | ❌ 不采集（需 L3） |
|:---|:---|
| 打卡时间 / 在校时长 | 消息条数 |
| 日程与连堂密度 | @次数 |
| 审批：加班、调休、请假 | 夜间消息占比 |
| 待办积压数量 | 会话时长、聊天对象 |
| 应用活跃时段 | 任何消息内容 |

右侧这一列在管理端界面上**明写出来**。主动声明放弃的能力，比罗列拥有的能力更能建立信任。

### 7.2 元数据要回到员工本人

如果 L1 数据只进管理看板，员工本人一无所感，那它就只是监测。**推给本人，它才从"监测"变成"关心"**：

> 这周你在学校待了 56 小时，有三天到晚上八点以后。

同样一组数字，进管理端是管理指标，回到本人是一句问候。这个双向流动是 L1 在伦理上成立的关键。

### 7.3 管理端的聚合门槛

- 部门/团队级聚合，**最小样本 8 人**，不足不予展示
- 不落个人档案，不与绩效、晋升、续聘挂钩
- 管理者看到的是趋势，不是名单

## 8. L2 · 按群的成员构成判定，不按行业

L2（机器人读取指定群消息）是唯一有条件可用的中间档。判定依据**不是行业，而是这个群里有没有外部人员**。

教研组群、年级组群全是本校教职工，可以开；家长群里有 46 位家长，不能开——**因为教师无法代家长同意**。

### 8.1 系统按群标注，管理员自行选择

```
群聊情绪感知 · 选择接入的群

☑ 三年级组教研群      18人 · 全部为本校教职工      可接入
☑ 语文教研组          24人 · 全部为本校教职工      可接入
☐ 三年级2班家长群     48人 · ⚠ 含 46 名非本校人员
☐ 家校沟通群         132人 · ⚠ 含 128 名非本校人员
```

### 8.2 不锁死，但把责任摊开

勾选含外部人员的群时，不禁止，但要求明确承担责任：

> ⚠️ 该群含 46 名非本校人员（家长）。
> 开启后他们的发言也会被系统读取。**你无法代他们同意。**
>
> ☐ 我已知悉，并确认由本单位承担相应告知责任
>
> 开启记录将留痕：操作人、时间、群名

**把决策权和责任一起交给管理者**，比系统硬性禁止更符合企业软件的真实运作方式，也更成熟。

## 9. 机器人会话的私密边界

机器人会话与网页应用有一个**结构性差异**，必须说清楚：

| | 消息路径 | 若企业已开通会话存档 |
|:---|:---|:---|
| **网页应用** | 浏览器 → MindBridge 服务端，**不经过 IM 消息通道** | 存档拿不到 |
| **机器人会话** | 员工 → **IM 平台服务器** → MindBridge | ⚠️ 可能被企业自有存档库记录 |

也就是说：员工对机器人说的话，**有可能进入企业自己的存档库——不是 MindBridge 读取的，也不是 MindBridge 能阻止的**。

### 9.1 分析照做，约束只在输出

需要澄清一个容易搞混的推论：**这不构成"机器人不做情绪分析"的理由**。

员工按下发送那一刻，暴露已经发生。此时拒绝分析，暴露风险一点没少，只是白白漏掉一个预警信号。所以：

| 行为 | 机器人侧 |
|:---|:---|
| 分析全文 | ✅ 照做 |
| 判定预警等级 | ✅ 照判，红色照样触发 |
| 建个案、通知疗愈师 | ✅ 照走（在服务端完成，不经过会话） |
| **回复中复述内容** | ❌ 不说"你刚才提到撑不住" |
| **回复中显示等级** | ❌ 不说"已触发红色预警" |

原则是：**读数照出，只管它开口说什么。**

### 9.2 措辞标准

机器人在会话里说的每一句，都按"可能被企业看到"来写：

- ❌ 「你连续三天提到撑不住了」— 泄露
- ✅ 「我在。要不要进来说两句？」— 无害

### 9.3 引导设计

机器人虽然有完整能力，但对话策略上**刻意不深挖**——不说"能多说一点吗"这类邀请深入的话，那是网页侧的工作。目的是减少员工在可能被看见的地方说重话。

但如果员工执意在机器人会话里倾诉：**照接、照分析、照预警。绝不因为地点不够安全就不接人。**

### 9.4 主动告知，而非替员工决定

检测到员工开始说重话时，主动提示：

> 这些话在这里说，可能会经过公司的系统。
> 想换个只有我们俩的地方吗？　[ 进去说 ]

把知情权还给员工，而不是替他决定要不要说。

> 📌 **待核实**：钉钉/企微/飞书中，「员工与企业自建应用/机器人的单聊」是否纳入会话存档范围。若不纳入，本节的约束可放宽。在核实之前，按最严格的情况设计。

## 10. 预警、复核与授权

| 原则 | 落实 |
|:---|:---|
| **AI 只识别，不诊断** | 输出的是情绪标签与预警等级，不是任何医学判断 |
| **所有预警须人工复核** | 疗愈师或 EAP 专员确认后再决定介入方式，AI 不自动定性任何员工 |
| **红色须员工授权才转接** | 系统只发出邀请：「我可以帮你联系一位真人疗愈师吗？」员工不点同意，**不会有任何人被通知** |
| **疗愈师看不到原文** | 个案只含匿名 ID、情绪标签、等级。想看原文需员工二次授权 |
| **否定语境保守降级** | 危机词处于否定语境时降级为黄色而非放行——宁可误报，不可漏接 |

## 11. 同一句话，六个人看到什么

**周敏在树洞里说的原话：**
> 「真的撑不住了，天天失眠，不想干了。」

| 视角 | 看到的内容 | 姓名 | 原文 |
|:---|:---|:---:|:---:|
| **周敏本人** | 全文，可随时永久删除 | — | ✅ |
| **AI** | 全文，仅用于判定等级 | ❌ 只有 `4A6B` | ✅ |
| **疗愈师 李佳** | `4A6B · 情绪耗竭 · 失眠7天 · 🔴红色`<br>想看原文，需周敏本人再次点头 | ❌ | ❌ |
| **HRBP 张敏** | `三年级组 · 情绪温度 5.4 · 红色个案 1 例` | ❌ | ❌ |
| **年级主任 / 直属领导** | 与 HRBP 同级视图，且样本不足 8 人的组不予展示 | ❌ | ❌ |
| **校长 / 系统管理员** | 无任何个人层面数据 | ❌ | ❌ |

**信息在每一层都在减少，而不是在每一层都能还原。**

> 脚注：若本单位已开通钉钉消息审计，员工与机器人的会话可能进入本单位自有存档库——这不是 MindBridge 读取的，也不是 MindBridge 能阻止的。为此机器人的回复措辞不复述任何具体内容，真正的深度倾诉引导至独立页面完成，不经过聊天通道。

## 12. 员工始终握有的控制权

| 权利 | 实现 |
|:---|:---|
| 随时清空 | 一键永久删除全部对话记录，不可恢复 |
| 撤回引用 | 已转发的内容随时撤回 |
| 关闭主动关怀 | 「别再提醒我」永久生效、当场生效 |
| 退出元数据统计 | 可从 L1 聚合中退出，不影响其他服务 |
| 拒绝转接 | 红色预警下仍可选择「我再想想」，无人被通知 |
| 知情 | 每一处数据使用都有可见说明，不藏在协议里 |

**产品愿意把自己的能力交给用户关掉，这件事本身就是论证。**

## 13. 合规对照

心理健康相关信息属于《个人信息保护法》定义的**医疗健康信息**，即**敏感个人信息**，适用最严格的处理规则。

| 法定要求 | 本方案的落实 |
|:---|:---|
| **最小必要原则** | 主动放弃 L2/L3，不申请会话读取权限；L1 只取行为元数据不取内容 |
| **单独同意** | 转发内容逐次确认；红色转接须员工单独授权；元数据接入独立告知并可退出 |
| **充分告知** | 脱敏结果当场展示；数据来源与用途在界面上直接说明，不藏在协议里 |
| **个人信息保护影响评估** | 部署前完成 PIA 并留档 |
| **个人的知情权与决定权** | 见第 12 节：删除、撤回、退出、拒绝，全部可自行操作 |
| **去标识化 / 匿名化** | 入口处单向哈希，盐由第三方托管，企业侧不可还原 |
| **告知义务不可转嫁** | L2 涉及外部人员时明确提示"你无法代他们同意"，并留痕责任人 |

劳动关系语境下的补充：员工监控无专门立法，但在《劳动法》与《个人信息保护法》框架下，需满足**目的正当、充分告知、范围最小**。本方案不采集任何通讯内容，且所有个人层面数据不与绩效、晋升、续聘挂钩。

> 📌 **待核实**：上述法条的具体条款编号需在写入方案书前核对现行文本。
