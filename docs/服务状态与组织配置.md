# 服务状态与组织配置

活动与疗愈师转介共用 `service_status` 的产品侧状态：`coming_soon`（筹备中）、`open`（开放中）、`paused`（暂停）、`retired`（结束）。状态独立于组织启停；组织配置可预先保存，服务暂停也不删除配置。

用户可以使用一项服务，须同时满足：产品侧为 `open`、本组织启用，以及该服务自身就绪。活动还需内容已发布、目录启用；疗愈师转介还需组织开启。推荐、活动开始和预约接口均执行此规则。红色风险识别与 12356 热线不受疗愈师状态影响。

活动的 `preview_visible` 允许筹备或暂停状态出现在活动库中，卡片展示介绍与状态，但不能开始。结束的服务不展示。尚未发布的线下活动首次导入时默认筹备中并允许预览；疗愈师转介的产品状态初始为筹备中。组织未覆写时采用标准启用配置，但产品状态未开放时不展示预约入口。

产品运营通过受 `INTERNAL_SERVICE_TOKEN` 保护的 `PUT /api/internal/service-status` 修改全局状态，请求体包含 `serviceId`（如 `activity:mindfulness-workshop` 或 `healer-referral`）、`status` 和布尔值 `previewVisible`。组织管理员只使用管理端配置页保存本组织启停，不能通过该页面修改全局状态。活动内容未就绪时，接口拒绝将其设为 `open`。开放疗愈师转介前应先确认真实接单安排与响应承诺。

部署顺序：先应用 care 数据库迁移 `0031`、`0032`，再部署员工端与管理端。已有活动状态在迁移时按内容就绪情况初始化；后续内容导入只为新活动创建初始状态，不覆盖人工调整过的状态。
