# 公开组织内测：创建邀请与测试手册

版本基线：2026-09-23 公开内测部署。本文供其他测试 Agent 独立执行；记录实际测试的 Git SHA、部署 URL、日期、浏览器和测试组织 ID。当前员工端地址为 `https://mindbridge-beta.pages.dev/`。旧地址 `https://mindbridge-app-8j6.pages.dev/` 在内部测试结束前继续开放，已经发出的邀请链接仍可使用。邀请原码由委托人单独提供，不保存在仓库。新邀请请使用新地址。

## 一、先建立可测环境

员工端 Cloudflare Pages 部署必须绑定新的统一 CARE D1 `mindbridge-beta-care`（配置见 `apps/employee/wrangler.jsonc`），且迁移已执行至 `0023_unified_organizations.sql`。不要将演示 seed 导入此库。钉钉身份库 `IDENTITY_DB` 仍独立。后台用于创建邀请的机器须已完成 Cloudflare 授权，并可执行项目自带的 Wrangler。测试前先确认公开 HTTPS 域名可访问、`/api/session` 在无 Cookie 时返回 401、`/api/auth/demo` 在生产环境关闭。

创建两个公开组织，用不同名称做隔离测试。以下命令在 `apps/employee` 目录运行，域名仅为示意；必须替换为实际已部署的员工端根地址：

```bash
node scripts/create-beta-organization.mjs "Mind Bridge 内测组" https://你的员工端域名 30 14
node scripts/create-beta-organization.mjs "另一家测试组织" https://你的员工端域名 30 14
```

参数依次为组织显示名、应用 HTTPS 根地址、最多**新加入的浏览器身份**数量、邀请有效天数。脚本输出组织 ID 与 `https://域名/?invite=...` 链接；原始邀请码只显示一次，数据库只存摘要。群内转发同一链接即可加入同一公开组织，不用预先登记微信号。转发链接不验证实际雇佣关系，因此不要把“持有链接”等同于“是该企业员工”。若要区分测试批次，按批次创建不同组织或邀请；当前脚本每次同时创建一个新组织和一条邀请。

组织可暂停或恢复，运行：

```bash
node scripts/manage-beta-organization.mjs <组织ID> paused
node scripts/manage-beta-organization.mjs <组织ID> active
```

`closed` 也可设置；脚本目前允许再改回 `active`。暂停后该组织的网页会话不应继续访问业务接口。名称用于员工端页头显示；匿名广场范围由组织 ID 决定，与名称文字是否相同无关。若两家公司都叫“Mind Bridge”，仍是两个隔离组织。公开组织没有钉钉考勤权限。

### 测试账号与数据准备

准备 A、B 两个公开组织邀请链接；至少三个相互隔离的浏览器环境：A1、A2 使用 A 链接，B1 使用 B 链接。建议使用不同浏览器资料目录或无痕窗口，避免同一浏览器的设备 Cookie 被新组织入口覆盖。准备一台手机微信内置浏览器、一台手机系统浏览器和桌面浏览器。企业端测试需真实钉钉工作台入口与授权人员；疗愈师端需既有疗愈师账号。切勿在真实人员聊天中输入身份证号、手机号等测试敏感信息；用明确标为测试的数据。

每个测试项记录：编号、环境、步骤、实际结果、期望结果、截图或视频、浏览器控制台与网络请求错误、严重度、是否可复现。隐私和跨组织问题标为阻断级，先停止扩大邀请范围。

## 二、入口、身份与组织（P0）

| 编号 | 操作 | 期望结果 |
| --- | --- | --- |
| ID-01 | 全新 A1 打开 A 链接 | 无钉钉或微信授权要求；自动进入聊天页；页头显示 A 的组织名称，URL 中邀请码被移除。 |
| ID-02 | 同浏览器刷新、关闭重开、隔天再进根地址 | 继续为同一匿名主体，聊天、活动、广场互动记录可见；不要求跨设备找回。 |
| ID-03 | A2 打开同一 A 链接 | A2 是另一假名主体，但能看到 A 组织广场；看不到 A1 的私人聊天。 |
| ID-04 | B1 打开 B 链接 | 页头显示 B 名称；B 广场初始不显示 A 的内容。 |
| ID-05 | A1 复制清洗后的根地址给新浏览器 | 新浏览器无邀请凭证，不能凭裸地址加入公开组织。普通浏览器应看到「请使用邀请链接进入」，并提示链接失效时联系邀请人。只有钉钉客户端里的失败才指向工作台。 |
| ID-06 | 邀请无效、过期、达到上限、组织暂停 | 不建立新身份，展示可理解的错误；不泄露组织成员数据。 |
| ID-07 | 已加入 A 的浏览器在邀请达上限后再次使用同链接 | 仍可复用已有身份；不会增加加入人数。 |
| ID-08 | 同浏览器再打开 B 链接 | 当前会话切换到 B，页头与广场随之切换；A、B 的聊天和活动不能混在一个假名下。再打开 A 链接时回到原来的假名，能看到 A 的聊天，且不增加 A 的加入人数。没有邀请、只打开根地址时，回到最近使用的那个仍在启用的组织。 |
| ID-09 | 清除站点 Cookie / 换设备 | 可经有效链接重新加入，但产生新假名主体；不承诺找回旧聊天。 |
| ID-10 | 点击退出，再仅打开根地址 | 会话及设备凭证清除，不应自动恢复；经有效邀请链接可重新进入。 |
| ID-11 | 钉钉工作台进入企业端 | 钉钉免登仍可用，业务会话有企业组织 ID；公开邀请不改变钉钉实名映射。 |

检查移动端微信内置浏览器的 Cookie 保存、网页分享方式、复制链接、返回和刷新。当前方案是网页，不是微信小程序；分享能力取决于网页链接，微信小程序认证与备案限制不适用于此网页入口。

## 三、功能回归（P0/P1）

聊天：空输入、长输入、中文输入法、网络中断、超时、连续快速发送、刷新恢复、长对话滚动、历史消息、清空会话后重新聊天。重点确认同一人的消息、模型回复和卡片没有重复写入，A2/B1 无法读到 A1 聊天。分别测试普通求助、活动推荐、风险提示和模型不可用时的降级文案；安全流程须由具备资质的人工复核，不用模型测试结果宣称临床安全性。

匿名广场：A1 发帖、A2 浏览/回复/互动、A1 删除；B1 始终不可见 A 内容。直接用 A 帖子的 ID 从 B 会话调用回复、互动和删除接口，均应拒绝。测试空内容、超长内容、攻击性内容和可识别个人信息过滤；帖子列表刷新、排序与重复点击应稳定。

活动与资源：打开推荐、开始、进行中刷新、完成、评价、再次打开，核对状态持久化与重复提交处理。新库已导入 10 项内容，其中 1 项线下工作坊因场地和时间为演示占位已停用；当前应看到 9 项线上活动，部分音视频内容标有“演示”。企业与公开组织均通过同一套管理后台按组织配置活动启停和推荐策略；内容文件仍由产品团队维护，各组织只决定对本组织开放哪些、推荐映射如何。

预约、授权、疗愈师：创建和取消预约、疗愈师接单/结案、用户批准或撤回上下文授权；任何角色不得在授权失效后继续读取会话原文。疗愈师账号体系仍是全局账号，需核对个案是否准确显示来源组织，以及疗愈师权限范围是否符合运营安排。

企业管理端：公开组织的聊天、广场、活动和研究事件不得进入企业 HR 报表。样本量低于阈值时继续抑制，不能通过逐日、细分维度或导出绕过；公开组织不得调用钉钉考勤节奏接口。公开组织管理员使用 `/?orgKey=...` 管理链接进入同一套 console，只看本组织聚合看板与配置；组织创建/暂停仍走受控命令。

## 四、UI、可用性与无障碍（P1）

在 320/375/390/768/桌面宽度、系统浅色/深色、浏览器字体放大至 200%、横竖屏测试四个主导航与长内容。记录截断、遮挡、布局跳动、触控目标过小、输入法顶起输入框、滚动位置丢失、弹窗无法关闭。重点观察首次进入是否理解“匿名组织”“公开广场”“私人聊天”的边界，页头组织名称是否清楚，邀请失败时是否知道下一步。

仅用键盘走完入口、切换导航、发消息、发帖、关闭弹窗；检查焦点顺序、可见焦点、按钮语义、表单标签、动态消息朗读、颜色对比与减少动态效果设置。用 VoiceOver 或 TalkBack 至少完成一次聊天与一次广场浏览。微信内置浏览器尤其检查安全区、底部导航与软键盘。

做 5 人左右的观察式可用性测试时，不先解释产品：请参与者找到聊天、说明谁能看到广场帖子、完成一次活动、找出隐私说明，再复述他们以为产品记录了什么。记录任务完成率、卡住位置和误解，不以访谈者提示后的成功算作自然完成。

## 五、数据、研究与隐私（P0）

用 Cloudflare D1 只读权限抽查 A、B 两组织：`organizations`、`subject_organizations`、`beta_memberships`、`sessions`、`posts`、`product_events` 的组织 ID 一致；钉钉真实身份只在 IDENTITY_DB。`product_events` 应能用组织 ID + 假名 ID 串起邀请进入、聊天、广场和活动，不能包含聊天原文、Cookie、邀请码、微信号或钉钉 userid。一次实际成功动作应对应合理事件；失败动作不应被记为成功。

导出命令示例：

```bash
node scripts/export-research.mjs <组织ID> 2026-09-01 2026-09-30 ./research-output "首轮内测行为分析"
```

检查四个 CSV 和 `export-audit.jsonl` 的范围、行数、假名关联、日期边界及 CSV 公式注入保护。输出目录包含敏感假名轨迹，只交给内部研究人员；企业联系人和评审材料只用满足披露阈值的汇总。测试 180 天清理规则时使用本地或隔离测试库，不要人为修改生产用户时间戳。`experience_feedback` 目前只有数据表，无提问界面；该表为空时不能报告主观帮助率。

检查参与者隐私说明是否准确写明：可按组织与假名关联个人活动、聊天原文的处理方式、180 天保留期、内部研究访问、企业只看阈值后的汇总、浏览器清除后身份无法找回。公开入口已有独立告知文案，但仍需测试者核对实际页面和理解程度。

## 六、稳定性、性能与安全边界（P1）

在正常网络、慢速移动网络、断网再恢复下测首次进入、发消息、广场加载和活动保存；记录响应时间分布及失败率。对同一邀请链接做并发加入和上限边界测试，核对 `join_count` 与实际成员数；邀请加入和计数已合为 D1 事务，但仍需在线并发验收。测试同一浏览器多标签页、短会话过期后的自动续签、组织暂停后的立即拒绝。

安全测试覆盖：伪造组织 ID/假名 ID、跨组织对象 ID、直接访问内部管理 API、CSRF、XSS（帖子/回复/组织名称）、SQL 注入、过长邀请码、暴力猜测邀请令牌、泄露在浏览器历史或错误日志中的令牌。只在授权测试环境进行压力和攻击性测试。不要在生产库跑清空、批量删除或演示 seed。

## 七、验收结论格式

测试报告先写实际部署版本和环境，再按 P0/P1 缺陷列出复现步骤、证据和影响组织。单独给出：入口是否可分享、组织是否隔离、私人会话是否隔离、企业权限是否隔离、研究数据是否可关联且无身份泄漏、核心功能是否可用、移动端 UI 是否可用。结论用“通过／有条件通过／阻断”，不要把单元测试通过直接写成真实用户测试通过。已知未完成项：独立的主观反馈问题界面、完整移动端与钉钉端浏览器验收。
