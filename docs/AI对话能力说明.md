## 2. 当前实现：内置规则引擎

Demo 中的每一次回应，都经过下面这条链路：

```
员工输入
  → 分句 · 词典匹配（7 类情绪 · 300+ 关键词，按小句加权，越靠后越重）
  → 语法与强度判别（否定语境排除误报；程度副词、感叹、叠字加权）
  → 危机词判定（含隐晦表达词库；否定语境保守降级为黄色）
  → 会话状态累积（连续信号升级；跨 session 共享画像）
  → 回应生成（片段组合，非查表）
```

### 几处值得说明的设计

**否定语境判别。** "不想活" 与 "谁说我不想活" 是完全相反的两句话。引擎会检查关键词
前方是否存在否定词，并排除 "不得不"、"没关系"、"没日没夜" 这类假否定，避免误报。
危机词若处于否定语境，**保守降级为黄色而非直接放行**——宁可误报，不可漏接。

**回应是组合出来的，不是查表。** 承接语、正常化语、追问语从各自片段库中按会话轮次
与输入哈希组合，同一情绪在不同轮次不会重复同一句话，避免机械感。

**判定与措辞是两件事。** 情绪标签、预警等级、场景识别属于"判定"；共情话术属于"措辞"。
这个分离是接入大模型的前提——见第 3 节。

## 3. 接入后的架构：规则层降级为安全兜底层

关键设计：**接入大模型不是替换规则引擎，而是在它中间插入一层。**

```
员工输入
  ↓
【前置安全层 · 同一套规则引擎】
   危机词判定优先。命中红色 → 不调用模型，
   直接走固定话术 + 转接邀请
  ↓
【大模型生成回应】
   系统提示词硬约束：不做诊断 · 不建议用药 · 不替代专业
   情绪标签与预警等级仍由规则层输出
   模型只负责"怎么说"，不负责"判定什么"
  ↓
【后置校验 · 同一套规则引擎】
   拦截诊断性措辞、用药建议、越界承诺
   不合格则回落固定话术
  ↓
送达员工
```

### 为什么必须这样设计

| 风险 | 规则层的作用 |
|:---|:---|
| 模型在高危场景自由发挥 | 红色信号**根本不进模型**，走固定话术 |
| 模型输出诊断性措辞 | 后置校验拦截，不合格则回落 |
| 模型服务超时或故障 | 回落规则引擎，服务永不中断 |
| 判定标准随模型版本漂移 | 情绪标签与等级由规则层产出，与模型无关 |

**"AI 只识别、不诊断" 这条原则，靠提示词是保证不了的，必须靠架构保证。**
把判定权留在确定性的规则层，把措辞交给模型，是这条原则唯一可靠的落法。

### 模型选型

DeepSeek / 通义等均可。判定逻辑与合规约束不依赖具体模型，
可随时替换，也支持私有化部署的开源模型，满足数据不出域要求。

## 4. 接入所需工作

| # | 工作项 | 说明 | 量级 |
|:---|:---|:---|:---|
| ① | 后端服务 | 承接会话、保管密钥（密钥不可下发前端） | 1 周 |
| ② | 系统提示词与边界约束 | 撰写 + 红队测试，确保不越界 | 1–2 周 |
| ③ | 前置／后置校验接线 | **规则引擎已具备，直接复用** | 2 天 |
| ④ | 超时与失败回落 | 回落到规则引擎，保证不中断 | 2 天 |
| ⑤ | 会话内容加密存储与保留期策略 | 含到期自动清除 | 3 天 |
| ⑥ | 成本与并发压测 | 按企业规模估算调用量 | 3 天 |

其中②是真正的工作量所在——**难的不是把模型接上，是让它不越界。**
而这恰恰是本方案已经想清楚的部分：边界写在架构里，不是写在提示词里。
