# MindBridge App：临时处理、技术债与待替换项

> 规则：凡是为了联调、路演、排障或阶段性交付而采用，但不应长期保留的处理，都登记在这里。代码注释不能替代本清单。完成替换后保留条目，并记录关闭日期、替代方案和验证证据。

## 当前未关闭

### TD-001：钉钉入口依赖人工递增 `build` 查询参数

- 状态：未关闭
- 当前值：钉钉移动端及 PC 端入口使用 `build=11`。
- 原因：钉钉桌面 WebView 曾长期复用旧 HTML 与旧 SDK，导致已部署的新代码没有生效。
- 当前作用：通过改变入口 URL 强制生成新的 WebView 缓存键。
- 风险：每次关键前端发布都要人工修改钉钉后台并重新发布应用版本，容易遗漏；查询参数本身不代表可追溯的构建版本。
- 最终方案：CI 生成内容哈希资源和明确的应用 release id；验证 HTML 缓存策略后，形成自动发布清单。若钉钉仍缓存入口 HTML，则只在发布流程中自动更新 release 查询参数，不由开发者手改。
- 关闭验收：连续两次生产发布无需临时排障即可让钉钉 PC/移动端加载正确 release，并能从日志定位客户端实际版本。

### TD-002：SDK 暂时使用完整 `dingtalk-jsapi` bundle

- 状态：未关闭
- 当前文件：`mindbridge-app/public/vendor/dingtalk-auth-v3.js`，约 612 KB。
- 原因：按需导入阶段曾发生导出对象与 API 注册顺序不一致，桌面 WebView 中 `requestAuthCode` 不可用。为先完成真实链路，当前从锁定版本的官方 npm 包构建完整 bundle，并只向业务代码暴露 `requestDingTalkAuthCode`。
- 正确性：当前不是多 SDK 兼容层，不包含 UA 分支、legacy fallback 或 `dd.ready` 双启动；真实 Mac 钉钉已经通过。
- 风险：体积偏大；未建立 bundle 导出与真机能力的构建时契约测试。
- 最终方案：在保持单一官方 API 路径的前提下，做可重复的最小 bundle；增加构建产物 smoke test，并在钉钉 PC 与移动端各做一条真机回归。
- 关闭验收：最小 bundle 在 PC/移动端均通过真实免登，且 CI 能在导出丢失时失败。

### TD-003：阶段 1 页面是验收页，不是最终员工首页

- 状态：代码已替换，待真机复验。
- 已完成（2026-09-03）：启动场景改为一次性隐私连接动画（约 1.2 秒，`prefers-reduced-motion` 下跳过），已有会话直达员工端；三个一级入口（倾诉树洞 / 匿名广场 / 我的）已上线；失败时才停留并给出重试与管理员诊断码。
- 已验证：本地 `wrangler pages dev` + 手工写入 care 本地 session，PC 与 375px 移动视口下三个 tab、发消息、红色同意卡、发帖、抱抱、我的页面均正常。
- 未验证：真实钉钉 PC/移动端中的完整启动动画与免登衔接。关闭前必须补这一条。

### TD-004：当前仅有单一真实成员完成端到端验收

- 状态：未关闭
- 已验证：一个测试企业成员在 Mac 钉钉完成真实授权、双库落库及关闭重开。
- 未验证：第二名成员、Windows、iOS、Android，以及两个成员之间的匿名身份隔离。
- 最终方案：至少用两个真实成员验证映射数量为 2、匿名身份互不相同、各自重开稳定；再补 PC 与移动端矩阵。
- 注意：验收只能比较匿名结果和记录数量，不把明文 `userid`、匿名 ID 或解密映射打印到前端和普通日志。

### TD-005：会话只实现固定 TTL，没有生产级清理与续期策略

- 状态：未关闭
- 当前值：`SESSION_TTL_SECONDS=1800`。
- 风险：过期记录会留在 D1；用户在使用过程中可能突然需要重建会话；缺少设备/会话撤销策略。
- 最终方案：定义滑动续期或明确重新认证规则；用 Cloudflare Cron/维护任务清理过期 session；保留最少必要审计指标，不保留可复原的身份数据。

### TD-006：静态资源 Cache-Control 规则会合并成冲突值

- 状态：未关闭
- 现象：全局 `Cache-Control: no-store` 与 vendor 的 `public, max-age=31536000, immutable` 在响应中被合并。
- 风险：不同 WebView/代理对冲突指令的处理不一致。
- 最终方案：重构 `_headers` 路由，使 HTML/API 与内容哈希静态资源分别得到单一、无冲突的缓存策略；用 `curl -I` 和钉钉真机同时验证。

### TD-007：演示数据尚未进入独立、可追踪的数据层

- 状态：未关闭
- 当前情况：丰富的模拟数据仍在单文件 Demo 中；真实 App 的 care D1 目前只有 session 表。
- 最终方案：演示基线使用独立 seed/migration 或明确的 `data_origin='demo_seed'` 标记；真实事件使用 `data_origin='live'`。聚合看板可以叠加两者，但 UI 必须持续标注模拟基线，且能一键重置演示租户。
- 禁止：伪造真实钉钉考勤、病假、聊天内容接口返回，或把样板数据描述成真实企业数据。

### TD-008：阶段 3 机器人尚未接入，同一匿名人的跨入口一致性只完成了数据模型准备

- 状态：未关闭
- 已有基础：identity relay 有 canonical anonymous identity 与 versioned alias 结构。
- 未完成：官方 Node Stream SDK 常驻服务、机器人发送者身份解析、定向通知、H5 与机器人同人验证。
- 最终方案：机器人只把钉钉发送者交给 Identity Relay，Care Domain 永远只接收 canonical anonymous id。

### TD-009：分诊仍是纯规则基线，外部大模型延后到阶段 3/4

- 状态：未关闭。已于 2026-09-03 决定：Stage 2 不接模型，外部大模型放到阶段 3 或 4。
- 当前实现：`functions/api/_lib/responder.js` 是回应生成的唯一入口，内部调用确定性规则引擎 `triage.js`；词典与话术逐行取自原型 Demo。
- 接入约束（写在 `responder.js` 顶部，改动必须同步）：模型层只能插在 `respond()` 内部，且只允许改写 `reply` 的措辞；`level` / `rule` / `resource` 必须继续由 `triage()` 产出，模型不得覆盖；模型调用失败时回落到规则回复，绝不因此降级危机判定。
- 接入前必须先补：对抗性测试集（改写、反讽、否定语境下的危机表达）。
- 需要同时评估：员工倾诉原文发往第三方模型属于数据出企业边界，与整套匿名隐私叙事冲突，接入前要给出明确的对外说明。

### TD-010：预约链路只实现员工侧，疗愈师接单在阶段 4

- 状态：Stage 2 范围内已完成（2026-09-03），阶段 4 前不关闭。
- 已完成：员工可从红色个案的知情同意卡片或「我的」页面提交匿名预约，获得随机个案编号（不从 anon_id 派生），可查看状态、可取消；`share_context_with_healer` 授权与撤销已实现。
- 有意保留的缺口：`status` 只会停在 `requested`，没有任何自动接单。演示时必须如实说明"疗愈师端在下一阶段"，不得表述成已经转接。
- 阶段 4 补齐：疗愈师接单、干预记录、二次授权查看上下文及其审计。

### TD-011：会话过期只做被动重连，尚无滑动续期

- 状态：未关闭，与 TD-005 相关。
- 当前表现：业务 API 返回 `SESSION_REQUIRED` 时前端自动回到启动流程重新免登，用户可见一次短暂的重连提示。
- 缺口：正在输入的内容会丢失；过期 session 行仍需定时清理。

### TD-012：广场内容检查是关键词与正则基线

- 状态：未关闭。
- 当前实现：服务端拦截攻击性词表与手机号/邮箱/证件号正则；前端提示只是同一规则的镜像。
- 风险：可被同义改写绕过；误伤正常表达的概率也存在。
- 最终方案：补充举报与人工复核路径，以及可审计的处置记录。

### TD-013：危机热线号码需要团队复核，企业 EAP 热线尚未配置

- 状态：未关闭。
- 当前值：`responder.js` 中的 `CRISIS_RESOURCES` 只有全国统一心理援助热线 12356（国家卫生健康委 2024 年 12 月发文启用，2025 年 5 月 1 日前各地热线并入）。
- 注意：官方要求为每日至少 18 小时服务，不是 24 小时；文案与单测都已禁止出现"24 小时"字样。
- 待办：上线前由团队再核实一次号码；补充客户企业自己的 EAP 热线（应为部署变量，不硬编码）。
- 风险等级：号码写错属于真实伤害，任何改动都必须复核后再发布。
