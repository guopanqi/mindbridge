# 组织、入口与地址（唯一源）

三端 README 不重复写这些，改结构只改这里。

## 组织模型

所有参与者都属于 `organizations` 中的一个组织，业务数据共用 CARE D1 `mindbridge-beta-care`。`kind` 只区分组织的接入方式：

| kind | 怎么来 | 举例 |
| --- | --- | --- |
| `enterprise` | 钉钉免登首次进入时自动建（`DINGTALK_ORG_ID` 决定 ID，默认 `org_enterprise_primary`） | 钉钉企业组织 |
| `beta` | 受控命令创建，可随时增减 | 公开内测组、隔离验证组、临时组织 |

`subject_organizations` 把匿名主体 (`anon_id`) 挂到组织，同一浏览器在不同组织是不同假名，互不可见。广场范围、聊天、活动都按组织 ID 隔离，与组织显示名文字无关。

## 入口

| 入口 | 对象 | 身份 |
| --- | --- | --- |
| 钉钉工作台 H5 | 企业成员 | 钉钉免登 → HMAC 匿名身份（`entry_channel='dingtalk'`），实名映射只在独立 `IDENTITY_DB` |
| 邀请链接 `https://<员工端>/?invite=...` | 任何组织（含公开/临时） | 无需钉钉/微信授权，直接建该组织的匿名会话（`entry_channel='beta_web'`） |
| 钉钉管理后台 / 企业 SSO | 企业管理员 / HR | console 会话绑定企业组织，看该企业聚合看板 |
| 组织管理链接 `https://<管理端>/?orgKey=...` | 公开组织管理员 | 同一套 console，会话绑定该公开组织，只看本组织数据 |

邀请：`apps/employee` 下 `node scripts/create-beta-organization.mjs "<显示名>" <员工端根地址> <加入上限> <有效天数> [管理端根地址]` 建组织+邀请+管理链接（原码只显示一次，库里只存摘要）；`node scripts/create-beta-admin-link.mjs <组织ID> [管理端根地址]` 轮换管理链接；`node scripts/manage-beta-organization.mjs <组织ID> active|paused|closed` 启停。裸根地址进不去（提示用邀请链接）；同一浏览器开另一组织链接会切换组织、换假名，不增加原组织计数。持有链接≠雇佣关系验证。

组织是聊天、广场、活动和报表的共同范围。钉钉与邀请链接只负责建立身份；进入业务层后都使用组织 ID 和匿名主体 ID。活动启停与干预矩阵按组织配置。办公数据能力单独授权，公开组织没有钉钉考勤或审批数据。创建/暂停公开组织仍走受控命令。

报表默认只统计本组织的真实数据。评审体验组额外有归属于本组织的 `demo_seed` 演示数据，可在管理端明确切换；其他组织不共享这份数据。历史上没有组织归属的全局模拟种子不再进入任何组织报表。评审数据也不能伪装为 `live` 真实使用。

## 地址

| 用途 | 地址 | 说明 |
| --- | --- | --- |
| 员工端对外（新） | `https://mindbridge-beta.pages.dev/` | 当前唯一对外地址，发邀请、写文档都用这个 |
| 员工端旧地址 | `https://mindbridge-app-8j6.pages.dev/` | 内部测试结束前保留，已发出的旧邀请仍可用；不要写进新材料 |
| 管理端/疗愈师 | `https://mindbridge-console.pages.dev/` | 同一套 HR 看板 + 疗愈师个案台；企业与公开组织靠入口区分 |

Pages 项目名仍是 `mindbridge-app`（员工端）/ `mindbridge-console`（管理端）；`mindbridge-beta` 是转发层。疗愈师个案需核对来源组织； HR 只能看聚合（样本 < 10 不出数，阈值硬编码）。旧的员工端 `/manage.html` 管理链接会跳转到 console。
