# MindBridge 路演专用需求

> 本文件登记**只服务于路演、不属于产品真实能力**的需求。
>
> 规则：这里的每一条都不进主干产品逻辑。实现时必须与真实功能物理隔离
> （独立入口、独立权限、独立数据来源），并且在界面上可被明确识别，
> 避免路演能力被误当成产品能力对外承诺。
>
> 当前状态：**全部未开始**。等主线功能完成、远端验收通过后再统一处理。

## R-001：AI 决策透视面板

- 需求：输入一句话，展示规则引擎的判定过程——识别到的情绪标签、强度、命中的关键词、
  被否定语境降级的词、最终 green/yellow/red 等级、命中的规则说明、以及将要推送的资源。
- 来源：原型 `mindbridge-demo.html` 的 `#xray` 面板。
- 路演价值：现场请评委说一句话，当场展示引擎如何判断，证明危机识别不是黑箱。
- 实现约束：
  - 只读，输入不落库、不产生聚合事件、不接触任何真实员工数据；
  - 必须放在管理端且仅管理员可见，每次调用写审计；
  - **不得**在员工端出现——规则说明对企业可解释，但不该对当事人贴标签。
- 备注：曾实现过后端与代理，已按决策撤除，需要时重做。

## R-002：时间加速 / 演示时钟

- 需求：把真实的时间间隔（活动回访 3 天、SLA 倒计时、会话过期、180 天保留期）
  在演示时压缩到秒级，以便现场完整演完一条链路。
- 现状：主干已全部改为**真实时间**，不做任何加速。
- 实现约束：
  - 只能通过独立的演示开关生效，且开启状态必须在界面上持续可见；
  - 绝不能影响真实员工产生的数据；
  - 加速态下产生的数据必须可与真实数据分别清理。

## R-003：演示租户一键重置

- 需求：管理后台提供入口，一键清空并重灌 `data_origin='demo_seed'` 数据，
  真实数据（`data_origin='live'`）不受影响。
- 现状：已有 `scripts/reset-seed.sql` 与 `npm run seed:reset`，但**后台没有入口**。
- 实现约束：需要管理员权限、二次确认、写审计日志。

## R-004：自动演示 / 剧本回放

- 需求：按预设剧本自动播放一条完整链路（员工倾诉 → 危机识别 → 同意 → 建案 →
  疗愈师接管 → HR 看板变化），用于无人值守展示或彩排。
- 实现约束：产生的数据必须标记为演示来源，且可一键清除。

## R-005：现场网络降级预案

- 需求：现场网络不可用或钉钉接口超时时的兜底展示方案。
- 备注：与 R-002、R-004 相关，一并设计。

## 不属于本文件的内容

以下是**产品真实能力**，不在此登记，也不允许用演示手段替代：

- 钉钉免登与匿名身份派生
- 规则分诊与危机判定
- 干预矩阵配置对员工端的实际生效
- 办公数据感知的真实钉钉接口连接
- 活动参与的前后自评效果度量
- 活动回访的真实时间排期
- 阈值抑制与部门样本遮蔽
- 数据保留期的真实清理
