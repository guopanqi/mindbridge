# 第十二部分　风险分析：伦理风险与数据安全

> 本章回答一个问题：**当 AI 进入员工的心理支持场景，凭什么值得被信任？**
>
> 我们认为这不是技术问题，是设计问题。一个员工只要怀疑自己被监听，这个系统对他就已经失效了——
> 后面再好的疗愈资源，也送不进一个关闭的心门。因此本方案把"克制"写进了产品结构，
> 而不只是写进承诺。

---

## 12.1 本项目面临的六类风险

| 风险类别 | 具体表现 | 严重性 |
|:---|:---|:---|
| **① 监控化风险** | AI 采集员工数据被理解为"公司在监视我"，导致员工回避、系统空转 | ★★★★★ |
| **② 敏感信息泄露** | 心理健康信息属敏感个人信息，一旦与身份关联外泄，后果不可逆 | ★★★★★ |
| **③ 标签化与歧视** | 情绪数据流入管理动作，员工因"心理状态"影响绩效、晋升、续聘 | ★★★★★ |
| **④ AI 误判与越权** | AI 对情绪状态下判断，形同无资质诊断；误判可能造成二次伤害 | ★★★★☆ |
| **⑤ 第三方权益受损** | 员工的沟通对象（家长、客户）从未同意，其信息被系统采集 | ★★★★☆ |
| **⑥ 危机响应失效** | 高危信号未被识别，或识别后无人接手，酿成实质伤害 | ★★★★★ |

以下逐一说明我们的应对。

---

## 12.2 风险① 监控化 —— 主动放弃能力，而不只是承诺不用

### 问题

企业办公软件（钉钉、企业微信、飞书）具备"会话内容存档"能力，技术上可获取员工全部聊天记录。
若 EAP 系统接入该能力，即可拿到最丰富的情绪数据——**也会在同一刻失去员工的信任**。

### 我们的做法：把可用数据划成四档，并明确停在前两档

| 档位 | 内容 | 授权方 | 本方案 |
|:---|:---|:---|:---|
| **L0** | 员工主动转发给系统的消息 | **员工本人，每次单独同意** | ✅ 采用 |
| **L1** | 考勤、审批、日程、待办等行为数据，**不含任何消息内容** | 企业常规授权 + 员工告知 | ✅ 采用 |
| **L2** | 指定群聊的消息内容 | 管理员 + 群内成员知情 | ⚠️ 可选，逐群判定（见 12.6） |
| **L3** | 全量会话内容存档 | 企业级合规开通 | ❌ **不申请** |

由此，本方案可以写下一句可被验证的承诺：

> **MindBridge 不申请任何一家办公软件的会话读取权限。**

### 为什么这不影响效果

被放弃的指标（消息条数、@次数、夜间消息占比）看似有力，实则可被替代。以中小学教师为例：

| 放弃的（属 L3） | 采用的（属 L1，说服力更强） |
|:---|:---|
| 家长群夜间消息 412 条 | 在校时长中位数 **11.2 小时**（早读 7:10 → 晚自习 18:20） |
| @我 37 次 | 周连堂课时 **22 节**，超基准 30% |
| 22 点后消息占比 61% | 加班调休审批 **14 次**，其中 **9 次落在周末** |

右侧全部来自考勤与审批接口，**未触碰一个字的通讯内容**，而它描述的是"这个人的一天有多长"，
比"手指有多忙"更贴近疲惫的本质。

于是形成清晰分工：**忙碌程度由 L1 的量来刻画，情绪刺痛点由 L0 的质来补足。**

### 元数据必须回流给员工本人

若 L1 数据只进管理看板，它就是监测；**回流给员工本人，它才是关心**：

> 「这周你在学校待了 56 小时，有三天到晚上八点以后。」

同一组数字，进管理端是管理指标，回到本人是一句问候。这一双向流动，是 L1 在伦理上得以成立的前提。

## 12.3 风险② 敏感信息泄露 —— 身份在入口处即被抛弃

心理健康信息属《个人信息保护法》定义的医疗健康信息，即**敏感个人信息**。本方案的处理原则是：
**不是"保护好身份"，而是"根本不持有身份"。**

```
员工从任一入口进入
        ↓
  HMAC-SHA256（用户标识 + 盐）
        ↓
     匿名编号 4A6B          真实身份在此刻被丢弃，系统内不再存在
```

三项关键设计：

1. **单向哈希**——从匿名编号无法反推真实身份
2. **盐由独立第三方托管，企业不可获取**——企业即使取得全部数据库，也无法重建对应关系
3. **多入口天然归一**——网页应用与聊天机器人使用同一算法，自动落到同一匿名身份，
   无需额外做账号打通，也就不存在一张可被查阅的映射表

呈现给人时使用化名（如「小溪-4A6B」）而非纯编号：**纯编号让人觉得自己是个案例，化名让人觉得自己是个人。**

---

## 12.4 风险③ 标签化与歧视 —— 信息逐层递减，而非逐层可还原

### 分层可见性

同一句员工原话「真的撑不下去了，天天失眠，不想干了」，在系统中的可见范围如下：

| 视角 | 看到的内容 | 姓名 | 原文 |
|:---|:---|:---:|:---:|
| **员工本人** | 全文，可随时永久删除 | — | ✅ |
| **AI** | 全文，仅用于判定等级 | ❌ 仅匿名编号 | ✅ |
| **持证疗愈师** | `4A6B · 情绪耗竭 · 失眠7天 · 红色`；<br>查看原文须员工本人再次授权 | ❌ | ❌ |
| **HRBP** | `三年级组 · 情绪温度 5.4 · 红色个案 1 例` | ❌ | ❌ |
| **直属主管** | 与 HRBP 同级视图，且样本不足 8 人的组不予展示 | ❌ | ❌ |
| **企业管理员** | 无任何个人层面数据 | ❌ | ❌ |

**信息在每一层都在减少，而不是在每一层都能还原。**

### 三条硬约束

| 约束 | 内容 |
|:---|:---|
| **聚合门槛** | 团队级统计最小样本 8 人，不足不予展示 |
| **不入档案** | 个人层面情绪数据不进入人事档案 |
| **不挂钩** | 不与绩效考核、晋升评定、合同续签发生任何关联，写入服务协议 |

管理者看到的永远是**趋势**，不是**名单**。

---

## 12.5 风险④ AI 误判与越权 —— AI 只读数，不诊断

### 边界

> **AI 不做诊断，只做"读数"和"吹哨"。真正的疗愈——解读报告、谈心疏导、工作调整、
> 一对一陪伴——全部由人完成。**

| 原则 | 落实 |
|:---|:---|
| **只识别，不诊断** | 输出情绪标签与预警等级，不产出任何医学判断 |
| **必经人工复核** | 所有预警须由疗愈师或 EAP 专员确认后再决定介入方式，AI 不自动定性任何员工 |
| **宁可误报，不可漏接** | 危机词处于否定语境时保守降级为黄色而非放行 |
| **不替员工下结论** | 当员工仅转发一段他人对话、自己一言未发时，系统**先承接情绪、再询问情况**，
  而不是从第三方的话里推断这名员工的心理状态 |

### 一个关键的技术设计：双通道分析

员工转发进来的聊天记录（如家长的质问），若直接投入情绪分析，会把**对方的攻击性**
算成**员工的情绪**，读数从根上就是错的。因此严格分为两条通道：

| 输入 | 作用 | 明确不做 |
|:---|:---|:---|
| **员工自己说的话** | 产出情绪标签与预警等级 | — |
| **转发进来的内容** | ① 识别沟通场景　② 强度加权 | **不产出情绪标签** |

场景识别用于把信号接回疗愈方案，例如识别为「家校沟通」即对应「痛点速写 + ABC 情绪理论」工作坊。

## 12.6 风险⑤ 第三方权益 —— 按群成员构成判定，并把责任落到人

员工的沟通对象（学生家长、客户）从未与本系统建立任何关系，其信息不应被顺带采集。

### L0 的解法：方向反过来

系统不主动读取任何会话。**是员工在需要时，自己把那一段递过来。**

```
员工在群里被某句话刺到
  → 长按 → 转发 → 选择 MindBridge
  → 系统立即脱敏：人名→角色代号、群名→泛称、手机号→移除
  → 原文不留存
```

脱敏对象包括：人名、群名与组织名、手机号、工号、身份证号、住址、金额。
经此处理，MindBridge 的数据库、疗愈师看到的内容、任何导出报表中，
都不会出现第三方的真实姓名。

### L2 的解法：不按行业一刀切，按群的成员构成判定

若企业希望开启群聊层面的情绪感知，判定依据**不是所属行业，而是这个群里有没有外部人员**：

```
☑ 三年级组教研群      18人 · 全部为本单位教职工     可接入
☑ 语文教研组          24人 · 全部为本单位教职工     可接入
☐ 三年级2班家长群     48人 · ⚠ 含 46 名非本单位人员
☐ 家校沟通群         132人 · ⚠ 含 128 名非本单位人员
```

选中含外部人员的群时，系统**不做硬性禁止**，而是把后果摊开、要求明确担责并留痕：

> ⚠️ 该群含 46 名非本单位人员（家长）。开启后他们的发言也会被系统读取。
> **你无法代他们同意。**
> ☐ 我已知悉，并确认由本单位承担相应告知责任
> 开启记录将留痕：操作人、时间、群名

**把决策权与责任一并交给管理者**，比系统单方面禁止更符合企业软件的真实运作方式，
也更利于责任可追溯。

## 12.7 风险⑥ 危机响应失效 —— 授权在前，SLA 在后

| 环节 | 机制 |
|:---|:---|
| **识别** | 危机词库覆盖隐晦表达（真实高危表达往往不直白），否定语境保守降级 |
| **授权** | 系统只发出邀请：「我可以帮你联系一位真人疗愈师吗？」<br>**员工不点同意，不会有任何人被通知** |
| **接管** | 授权后生成个案工单，推送至持证疗愈师队列 |
| **时限** | 首次电话确认 SLA 2 小时，超时自动升级 |
| **闭环** | 疗愈师标记处置结果，系统追踪情绪轨迹变化 |
| **管理侧** | HRBP 仅见红色个案计数 +1，无权查看任何详情 |

**授权前置**是这一环的核心：宁可少接一个不愿被接的人，也不做未经同意的干预。
一次未经允许的"关心"，会让员工永久关闭这个通道。

---

## 12.8 员工始终握有的控制权

| 权利 | 实现方式 |
|:---|:---|
| 删除 | 一键永久清空全部对话记录，不可恢复 |
| 撤回 | 已转发的内容随时撤回 |
| 免打扰 | 「别再提醒我」永久生效、当场生效 |
| 退出统计 | 可从元数据聚合中退出，不影响其他服务的使用 |
| 拒绝转接 | 红色预警下仍可选择「我再想想」，无人被通知 |
| 知情 | 每一处数据使用在界面上直接说明，不藏在协议条款里 |

> **一个愿意把自己的能力交给用户关掉的产品，才配谈信任。**

---

## 12.9 合规对照

| 法定要求 | 本方案的落实 |
|:---|:---|
| **最小必要原则** | 主动放弃 L2/L3；L1 只取行为元数据，不取任何通讯内容 |
| **单独同意**（敏感个人信息） | 转发内容逐次确认；红色转接须员工单独授权；元数据接入独立告知并可退出 |
| **充分告知** | 数据来源与用途在界面上直接说明；脱敏结果对员工可见 |
| **个人信息保护影响评估** | 部署前完成 PIA 并留档 |
| **知情权与决定权** | 见 12.8：删除、撤回、退出、拒绝，全部可自行操作 |
| **去标识化** | 入口处单向哈希，盐由第三方托管，企业侧不可还原 |
| **告知义务不可转嫁** | L2 涉及外部人员时明确提示"你无法代他们同意"，并留痕责任人 |

劳动关系语境下的补充：员工数据处理虽无专门立法，但在《劳动法》与《个人信息保护法》框架下，
须满足**目的正当、充分告知、范围最小**三项要求。本方案不采集任何通讯内容，
且所有个人层面数据不与任何人事决策挂钩。

## 12.10 其他实施风险与对策

| 风险 | 对策 |
|:---|:---|
| **企业接受度** | 提供 1–2 周轻量试点，先跑通用预防型场景，用数据说话再谈扩容 |
| **员工使用率低** | 匿名 + 24 小时可用 + 主动关怀触达，降低求助门槛；不设强制打卡类任务 |
| **疗愈师资源不足** | 分级响应：绿色自助资源、黄色团体工作坊、红色一对一，仅红色占用稀缺资源 |
| **预算风险** | 模块化采购，AI 轨道与疗愈轨道可分期实施 |
| **数据跨境** | 数据存储于境内，不涉及跨境传输 |
| **供应商依赖** | 办公软件侧仅使用标准开放接口，不依赖任何单一平台的专有能力 |

---

## 12.11 小结

本方案在数据上的核心主张，可以概括为一句话：

> **我们不去读员工的聊天——是员工在需要的时候，自己把那句话递过来。**

四档权限中主动停在前两档、身份在入口即被抛弃、信息逐层递减、AI 只读数不诊断、
危机响应授权前置——这些不是对监管的被动应付，而是这套系统能够真正被员工使用的前提。

**让 AI 敢被信任，本身就是本方案的创新之一。**
