# MindBridge · 办公平台接入方案

> **可行性说明文档。** Demo 演示的是交互形态与判定逻辑，未连接真实的钉钉／企业微信／飞书接口。
> 本文说明真实接入如何完成、需要哪些权限。三条通道均为三家平台的标准开放能力。

## 1. 三条接入通道

MindBridge 与办公平台之间只有三条通道，每条通道拿到的东西、由谁授权，都是明确的。

| 通道 | 形态 | 授权方 | 拿到什么 |
|:---|:---|:---|:---|
| **① 自建应用（H5）** | 工作台图标进入的网页 | 员工首次 OAuth 授权 | 员工在网页内主动输入的内容 |
| **② 企业内部机器人** | 消息列表中的会话 | 无需二次授权（已在 IM 内） | 员工发给机器人的消息、员工主动转发的记录 |
| **③ 开放接口** | 服务端调用 | 企业安装应用时一次性授权 | 考勤、审批、日程、待办等行为元数据 |

**不使用第四条通道**：会话内容存档（全量聊天记录读取）。理由见
[伦理风险与数据安全.md](伦理风险与数据安全.md) 第 12.2 节。

## 2. 通道① 自建应用（H5）

### 接入方式

1. 在管理后台创建企业内部应用，配置应用首页地址（H5 页面 URL）
2. 员工点击工作台图标 → 平台带 `code` 跳转到应用首页
3. 应用后端用 `code` 换取用户标识（`userid` / `open_id`）
4. **拿到标识的同一刻做单向哈希，随即丢弃原值**

```
平台回调 code
   → 服务端换取 userid
   → HMAC-SHA256(userid + salt)  →  4A6B
   → userid 不落库、不写日志
```

盐由独立第三方托管，企业侧不可获取；哈希单向不可逆。此后系统内不存在可还原的真实身份。

### 所需权限

| 平台 | 权限点 |
|:---|:---|
| 钉钉 | 通讯录个人信息读权限（仅用于换取标识后立即哈希） |
| 企业微信 | 应用身份验证（`OAuth2` 网页授权） |
| 飞书 | 应用身份验证（`contact:user.base:readonly` 或等效） |

> 三家都只需最基础的身份换取权限，不需要通讯录全量读取。

## 3. 通道② 企业内部机器人

这是本方案 L0（员工主动转发）与主动关怀触达的载体，也是最需要说清楚的一条。

### 接入方式

1. 为内部应用开启机器人能力，机器人出现在员工的消息列表中
2. 配置消息接收回调地址（或使用长连接 / Stream 模式）
3. 员工发消息或转发记录 → 平台推送到回调 → 服务端处理后调用发送接口回复
4. 主动关怀由服务端在满足触发条件时直接调用发送接口，无需员工先说话

### ⚠️ 企业微信的一处关键限制

**企业微信有两种"机器人"，只有一种能用：**

| 形态 | 能发 | 能收 | 可用性 |
|:---|:---:|:---:|:---|
| **自建应用会话** | ✅ | ✅ | ✅ **必须用这个** |
| 群机器人（webhook） | ✅ | ❌ | ❌ 只能单向推送，收不到任何消息 |

企业微信的"群机器人"本质是一个**只出不进的 webhook 喇叭**。若误把它当作机器人载体，
「员工转发消息给 MindBridge」这条通道会**完全不可用**——员工转发过去，系统什么也收不到。

在企业微信部署时，L0 通道必须走**自建应用会话**（应用本身在员工的消息列表中就是一个会话对象）。

钉钉与飞书的机器人均为双向，无此问题。

### 转发路径的两种形态

| 平台 | 路径 | 步数 |
|:---|:---|:---:|
| 飞书 | 长按消息 → 直接出现「MindBridge」（消息快捷操作） | 1 |
| 钉钉 / 企业微信 | 长按消息 → 转发 → 选择 MindBridge | 2 |

Demo 演示的是通用的两步路径，可在支持消息快捷操作的平台上降为一步。

> 📌 待核实：钉钉是否提供等效于飞书「消息快捷操作」的能力。若有，教育行业部署可优化为一步。

## 4. 通道③ 开放接口（L1 行为元数据）

### 采集字段与来源

| 指标 | 来源接口 |
|:---|:---|
| 在校／在岗时长 | 考勤打卡记录 |
| 连堂课时、会议密度 | 日程 |
| 加班、调休、请假频次 | 审批单据 |
| 待办积压 | 待办任务 |

**全部为行为元数据，不含任何通讯内容。** 消息条数、@次数、夜间消息占比这类指标
需要会话存档权限，本方案不申请，因此拿不到，也不需要。

### 调用方式

服务端定时拉取（建议每日一次，非实时），聚合到团队维度后写入看板；
个人维度仅用于回流给员工本人的关怀文案。

### 各平台能力强弱

| 数据 | 钉钉 | 企业微信 | 飞书 |
|:---|:---:|:---:|:---:|
| 考勤打卡 | ★★★ 最完整 | ★★ | ★★ |
| 审批单据 | ★★★ | ★★ | ★★ |
| 日程密度 | ★★ | ★★ | ★★★ 含忙闲状态 |
| 待办 | ★★ | ★ 较弱 | ★★★ |
| 特有信号 | 智能人事 | — | OKR 进度 |

## 5. 部署形态

```
钉钉/企微/飞书  ←→  MindBridge 服务端  ←→  管理后台 / 疗愈师工作台
   （客户企业）        （SaaS 或私有化）
```

| 项 | 说明 |
|:---|:---|
| 部署周期 | 标准 SaaS 接入 1–2 周；私有化部署 4–6 周 |
| 数据存储 | 境内，不涉及跨境传输 |
| 私有化 | 支持整套私有化部署，满足金融、国企的数据不出域要求 |
| 平台依赖 | 仅使用标准开放接口，不依赖任何单一平台的专有能力 |

## 6. 企业需配合的事项

| 事项 | 说明 |
|:---|:---|
| 创建内部应用并授予权限 | 见第 2、3、4 节所列权限点，均为基础权限 |
| 员工知情告知 | 元数据采集范围、用途、退出方式，需以企业名义告知全员 |
| 指定 EAP 对接人 | 接收红色个案通知，配合疗愈师完成闭环 |
| 疗愈师排班 | 保障红色个案 2 小时内首次响应 |
